# The API

The API so far. Every request needs the login described in [Access](access.md).

- `GET /api/health`: `{ "status": "ok" }`. What `k-bench status` asks; guarded like every other route (it needs the owner's login).
- `GET /api/state`: Workspaces with their Sessions (`kind`, `"shell"` or `"claude"`; `role`, `"prime"`, `"worker"` or `null` for an Other Session; `running` or `stopped`; and `bell`). The Launch options and the conversation ID of a Claude Session are not in it.
- `POST /api/sessions/:id/restart`: starts a Stopped Session again in its Workspace folder, same id and name (a running Session is left alone; 422 when the folder is gone, for either kind). A shell Session gets a fresh shell. A Claude Session resumes the Claude conversation last running in it: Claude Code is run with `--resume <conversation ID>` and every stored Launch option again, since `--resume` does not restore `--settings`. Claude Code saves a conversation only after its first message, so when the owner quit without sending one, `--resume` fails with exit 1 and the launcher runs `--session-id <conversation ID>` with the same options instead. That cannot fork or overwrite a conversation, because `--session-id` fails with exit 1 on an ID that already has one. k-bench decides by exit statuses alone (ADR 0005). The conversation ID is the one k-bench gave the Session at launch until Claude Code reports another through k-bench's `SessionStart` hook (after `/clear`, `/resume` or `/branch`); then it is that one. If both attempts fail, the error hold below applies. There is no dialog and no request body.
- `GET /api/directories?path=`: the subfolders of `path` for the folder picker, plus `root`, the configured picker root (Home); 422 if the path is not an existing absolute folder. Without `path` it lists where the picker opens: the parent of the most recently created Workspace's folder, or the picker root when there are none (or that parent is gone).
- `POST /api/workspaces` `{folder, name?, createMissingFolders?}`: the name defaults to the folder name, with a "(2)"-style suffix when taken; an explicit name that is taken gets 409, a missing folder 422. A folder has at most one Workspace: a folder another Workspace already has gets 409 with `{error, workspace: {id, name}}` naming that Workspace, so a client can take the owner there. Folders are compared after resolving to an absolute path. The rule is checked here, not by the database, so Workspaces that already shared a folder before it came in are left as they are. The new Workspace's Prime and Worker are recorded with it, in one transaction: Claude Sessions named "Prime" and "Worker", each with a fresh conversation ID. Neither is started. Every launch of one, first start and every restart, passes k-bench's fixed Launch options for its role (`ROLE_LAUNCH_OPTIONS` in `src/shared/launch-options.ts`), not what is stored with it. With `createMissingFolders: true`, a folder that doesn't exist is made, with any missing folders above it, from the top down, after every other check has passed (so a folder another Workspace has is refused before anything is made). If one can't be made, the 422 names it, no Workspace is created, and the folders already made stay.
- `POST /api/workspaces/:id/sessions` `{name?, claude?}`: creates a Session (201 `{id, name}`). Without `claude` it is a shell Session. With `claude` (an object; 422 otherwise) it is a Claude Session: k-bench generates its conversation ID and starts Claude Code in the Workspace folder through the owner's login shell with `--session-id <conversation ID>`. The Launch options are `claude: {model, effort, advisor, focusView}`; a field left out is Default. An unknown value, or a `claude` that is not an object, gets 422 naming the field (`claude.model`), and no Session is created. k-bench does not check which model and advisor go together: Claude Code rejects a bad pairing, and the error hold below shows its message. The Launch options are stored with the Session, and a restart passes them again. "Default" passes no flag, so the owner's own Claude Code settings apply.
  - `model`: `default`, `fable`, `opus`, `sonnet` or `haiku`, passed as `--model <alias>`.
  - `effort`: `default`, `low`, `medium`, `high`, `xhigh` or `max`, passed as `--effort <level>`.
  - `advisor`: `default`, `off`, `fable`, `opus` or `sonnet`, passed as `--advisor <alias>`. `off` passes no flag (there is none) and sets `CLAUDE_CODE_DISABLE_ADVISOR_TOOL=1` for that launch only.
  - `focusView`: a boolean. `true` adds `"viewMode":"focus","tui":"fullscreen"` to the `--settings` every launch passes (both keys, because focus view needs the fullscreen renderer). `--settings` also carries k-bench's silent `SessionStart` hook, which reports the conversation Claude Code is on so a restart resumes it (ADR 0005). It applies to that launch only and leaves the owner's Claude Code settings files unchanged.

  Claude Code quitting with status 0 makes the Session Stopped; with another status the pane keeps the error on screen ("Claude Code exited with an error. Press any key to close.") until a key is pressed, then the Session is Stopped. A blank name gives "session N", a taken name or "Prime" or "Worker" 409, a Missing Workspace 422.
  Creating a Claude Session also records its Launch options on the Host, in a one-row table of their own, replacing the last ones (a refused creation records nothing; the name is never recorded). There is no write endpoint.
- `GET /api/claude/launch-options`: the Launch options last used to create a Claude Session, as `{model, effort, advisor, focusView}`; all `"default"` with `focusView` false when none has been created. The New Claude dialog reads it each time it opens, so every device opens with the same choices. They survive a k-bench restart.
- `PATCH /api/workspaces/:id` `{name?, folder?, createMissingFolders?}`: rename and/or change the folder (`createMissingFolders` works as for `POST`); 409 for a taken name, 409 with `{error, workspace: {id, name}}` for a folder another Workspace has (its own folder is fine), 422 for a blank name or a folder that does not exist (neither change is made if one is refused), 404 for an unknown Workspace.
- `PUT /api/workspaces/order` `{ids}`: the full ordered list of Workspace ids (422 unless it is every Workspace exactly once).
- `DELETE /api/workspaces/:id`: ends every Session's shell, then removes the Workspace (204). The folder on disk is never touched.
- `PATCH /api/sessions/:id` `{name}` renames a Session (409 if the name is taken in its Workspace or is "Prime" or "Worker", 422 if empty); `DELETE /api/sessions/:id` ends its shell and removes it (204). A Prime or Worker can be neither renamed nor deleted (409). Session names are unique per Workspace; created without a name, a Session gets "session N" with the next free N.
- `GET /api/sessions/:id/terminal?cols=&rows=` (WebSocket): output arrives as binary frames; input and resizes go out as JSON text frames, and close code 4410 means the terminal has ended (the Session was deleted, or is Stopped), so the client must not reconnect. The protocol is defined once, in `src/shared/terminal-protocol.ts`, which the server, the browser and the tests all import. Input the terminal sends by itself (answers to tmux's queries) is marked `automatic`, so it never takes the window's size for its device.
- `GET /api/events` (WebSocket): sends the full state (same shape as `GET /api/state`) as a JSON text frame on connect and again whenever it changes, whether from a request on any device or from something tmux-side such as a shell exiting. Clients send nothing. Each frame also carries a `revision`, and every successful change request answers with a `State-Revision` header: a client waits for a snapshot at that revision or later to see its change. The snapshot shape, the header name and the decoding are defined once, in `src/shared/state-protocol.ts`; the browser's `web/src/stateClient.ts` is the client.
