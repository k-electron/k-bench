# Draft: SDK capabilities (for `docs/claude-agent-parity.md`)

A draft of the parity checklist's new section, kept on this research branch. It is written to be pasted into `docs/claude-agent-parity.md` as a new `## SDK capabilities` section once the map's spec settles the open tickets. Until then, the **Ticket** column names the map's research tickets, not delivery tickets.

## SDK capabilities

Every capability of the Agent SDK, as its documentation stood on 2026-11-19 (SDK 0.3.328) plus what the installed `sdk.d.ts` (0.3.325) adds, and for each one the development outcome it serves and how a Claude Agent reaches it. This is the drift guard for SDK releases: when the SDK grows an option, a method, a message or a guide feature, it gets a row here.

### How to read it

The **Outcome** column is one of the map's eight: Start and pick up, Steer, Approve safely, See the work, Use your setup, Review and undo, Stay within limits, Recover. A dash means none.

The **Where** column says one of four things:

- **Claude Agent**: k-bench reaches it, in the web interface or in how it launches Claude Code. The Notes cite the code.
- **Config**: reached through Claude Code configuration k-bench already loads (settings files, `.claude/agents/`, `.mcp.json`, plugins, command hooks, or the environment). The Notes name the route.
- **Gap**: an outcome needs it and neither route exists. The **Ticket** column is the map ticket that settles it; `new` means no ticket covers it yet.
- **Out of scope**: program-only (it serves a program reading the SDK, not an interactive session), out by a standing decision, or no outcome needs it. The Notes give the reason.

**Done** is `[x]` for Claude Agent and Config rows, `[ ]` for Gap rows, `n/a` for Out of scope. Paths are from the repository root. `GA1`–`GA4` are the four reviews on the `research/agent-sdk-gap-analysis` branch (1 messages and controls, 2 interaction loop, 3 extensions and sessions, 4 operations), with their section or row.
