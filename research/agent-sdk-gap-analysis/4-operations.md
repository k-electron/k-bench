## N/A for an operator

- **Structured outputs** (all of `structured-outputs.md`, plus troubleshooting § Structured outputs): this is for builders. The owner's Claude Code doesn't set `outputFormat`.
- **OpenTelemetry** (`observability.md`): nothing for k-bench to build. The owner's `OTEL_*` and `CLAUDE_CODE_ENABLE_TELEMETRY` already reach `claude` through `...process.env` (`session.ts:78`). One small caveat: Stop kills `claude` after 2s, so the last telemetry batch may be lost.
- **Dollar cost tracking**: `total_cost_usd`, `modelUsage` cost, per-step usage accounting and cache-TTL pricing. The owner doesn't want pricing shown.
- **`maxTurns` and `maxBudgetUsd`**: these suit unattended builder workloads. The budget is in dollars.
- **Hosting patterns**: ephemeral, hybrid and multi-agent containers, `SessionStore` and `mirror_error`, `startup()`/`prewarm()`, scaling formulas, load-balancer pinning.
- **Isolation and network controls**: containers, gVisor, Firecracker, the sandbox-runtime install, egress proxies, credential injection, multi-tenant isolation. Inbound access is the tailnet (ADR-0003).
- **Python-only errors**: `CLINotFoundError` on the `PATH`, `max_buffer_size`, Windows batch scripts, "Not connected".
- **Quickstart and examples**: API-key setup and demo apps.

## Policy note (not a code gap)

`overview.md` § Get started says: "Unless previously approved, Anthropic does not allow third party developers to offer claude.ai login or rate limits for their products, including agents built on the Claude Agent SDK." k-bench is published on npm as `@k-electron/k-bench` (MIT), and its Claude Agent runs only on a claude.ai subscription (`account.ts`). Using it for themselves is the owner's own business. **Owner, 2026-11-19: the policy is fine; no action.** See README for the primary-source reading. Distributing it puts it close to what that note describes, so it's worth the owner checking. Separately, § Branding guidelines allows the name "Claude Agent" but not "visual elements that mimic Claude Code", and the Transcript copies the Claude Code terminal's look on purpose ("in Claude TUI's shape", including the `✻` spinner). That is also worth a look while the package stays public.

## The 5 most important gaps in this slice

1. **An oversized message can lock the Pane in a reconnect loop.** One replay line over 16M chars makes the relay drop the runtime connection, and the browser asks for the same replay again (`lines.ts:8`, `agent-sockets.ts:115-121`, `replay.ts:19-31`). A screenshot- or PDF-heavy turn could leave an Agent unreadable on a device, so the fix is to split replays into pages or chunks and cap or summarise huge entries.
2. **Usage credits are invisible.** The rate-limit reader throws away `allowed` events and every overage field (`uncommon.ts:469-492`), so moving onto pay-per-use usage credits shows nothing. Given the subscription-only rule in `account.ts`, k-bench should at least flag "now using usage credits" on the Pane and the row.
3. **No glanceable plan-usage meter.** Limits apply to the whole account, but warnings land in a single Agent's Transcript, and the status line shows only the model and context left. A small 5-hour and weekly meter (from `rate_limit_event`, or the experimental usage call) on the status line or the sidebar would serve a phone operator running several Agents.
4. **Diagnostics are lost.** No `stderr` callback is set, the exit reason is cut to 1000 chars, and a runtime crash before its handlers exist leaves only "exited unexpectedly" (`session.ts:131-155`, `main.ts:270-273, 376-390`). Teeing Claude Code's and the runtime's stderr into a capped file in the Agent's folder would make Stopped Agents debuggable.
5. **Stalls and subagent retries are hidden.** `tool_progress` heartbeats and `subagent_retry` are logged but never shown (`unsupported.ts:54`, no other handling), so a subagent waiting on a rate limit or a hung tool reads as normal work. Showing "retrying (rate limit)" on the subagent's line and a "no output for N min" hint would let the owner choose to stop it from a phone.
