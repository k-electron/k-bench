## Handled (one line each)

- **canUseTool allow/deny with message, "tell Claude what to do differently".** `asks.ts:138-183`, `PermissionPrompt.tsx`.
- **`suppressAlwaysAllowRule`.** Honoured in `asks.ts:99` and `PermissionPrompt.tsx:71`.
- **Ask withdrawn by `signal`.** Logged `cancelled` (`asks.ts:103-111`).
- **First answer wins; asks survive disconnects.** No timeout and no `defer` (`asks.ts:62-130`).
- **AskUserQuestion.** 1-4 questions, multiSelect, Other; answers validated by `answersFit` (`QuestionPrompt.tsx`, `asks.ts:142-155`).
- **Plan approval via ExitPlanMode, with feedback on reject; mode restored after.** `PlanPrompt.tsx`, `mode.ts`.
- **Modes default/acceptEdits/plan/auto.** Cycled, auto gated on `supportsAutoMode`, and the fall back to default after a model switch is read from `system/status` (`mode.ts:59`). dontAsk and bypass are shown but never entered from the web (`agent-protocol.ts:288-295,714`).
- **Owner's rules, mode and hooks evaluated before canUseTool.** No `allowedTools`, `permissionMode` or `settingSources` set (`session.ts:131-154`).
- **Streaming input, queued prompts and "(queued)".** Interrupt keeps queued prompts. Images go as base64 blocks (`session.ts:86-111,226-244`, `prompts.ts`).
- **Partial text streaming, cut-off streams and late-joiner snapshot.** `transcript.ts:140-178`, `live.ts`.
- **Result errors.** `error_*` and `is_error` become a "problem" line, and an interrupt is not counted as an error (`uncommon.ts:515-534`).
- **A crash result ending the process.** The Agent is Stopped, with the reason shown.
- **Compaction.** Running, done and failed are shown, and context left is polled (`uncommon.ts:269-310`, `session.ts:209-220`).
- **api_retry and rate-limit lines.** `uncommon.ts:407-437,470-500`.
- **Background/subagent task messages.** Read for the task lines (`items.ts:376-386`).

## Docs vs installed types

Nothing the docs in this slice describe is missing from `sdk.d.ts` 0.3.325. `previewFormat`, `includeHookEvents`, `onUserDialog`/`supportedDialogKinds`, `PermissionResult.interrupt`, `priority`, `permission_denied`, `terminal_reason` and the refusal messages are all there.

The installed types go further than the docs:

- `CanUseTool` returns `PermissionResult | null` and adds `mcpServer` and `matchedAskRule`.
- There is a `list_permission_rules` control request, relevant to the parity doc's "/permissions: view the rules — no public SDK API". It is not exposed as a `Query` method.
- The `ask_user_question_unanswered_v1` annotations exist only as wire-protocol capability text, not as a public type.

## The 5 most important gaps

1. **No interrupt or redirect while an ask is open** (`PromptDock.tsx:75`). The Composer, its Interrupt button and Esc are all hidden whenever a panel is up, so the owner has to answer every queued ask before they can stop or redirect Claude. In the TUI one Esc denies and stops the turn.
2. **Auto-mode and rule denials have no reason** (`unsupported.ts:85`, `uncommon.ts:464`, `items.ts:322`). `system/permission_denied` is classed as known but has no line, and a rejected tool shows a bare red "Denied" with its message dropped. With Auto mode in the cycle, the owner can't tell what blocked Claude or why.
3. **The permission panel hides why it is asking** (`PermissionPrompt.tsx:76-84`, `transcript.ts:301-315`). `decisionReason` (dangerous rm, a hook's reason, an org-required approval, an auto-mode escalation), `blockedPath`, `matchedAskRule` and the subagent's ID never reach the screen. The highest-risk prompts look exactly like routine ones.
4. **Hook output is mostly invisible or misattributed** (`session.ts` lacks `includeHookEvents`; `items.ts:415` ignores assistant `is_meta`). Only SessionStart/Setup hook responses arrive, info-level informational lines are dropped, and the binary sends a hook's `systemMessage` as an `is_meta` assistant message that k-bench would draw as Claude's own reply. The parity row "hook output [x]" overstates what is covered.
5. **The default task tools aren't drawn as a task list, and MCP elicitations are auto-declined** (`uncommon.ts:709`, `session.ts:146-149`). On models that have task tools, Claude Code's default is TaskCreate/TaskUpdate, which show as raw tool lines instead of the checklist. Every MCP form, URL sign-in or elicitation-based permission prompt is declined outright, and Open in terminal can't bring it back.
